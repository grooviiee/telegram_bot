# 지금이니! 관심종목 가격 조건 알림

봇과의 **개인 채팅**에서 관심종목을 등록하면 매시간 가격을 확인하고, 등록한 조건을
충족할 때 Telegram 알림을 보냅니다. 기존 즐겨찾기·공시 알림과 별도로 관리합니다.

| 명령어 | 동작 |
|---|---|
| `/timing 삼성전자` | 자동 조건으로 등록 |
| `/timing 005930 70,000` | 최신 가격이 70,000원 이하이면 알림 |
| `/timing 삼성전자 70000` | 같은 종목의 조건을 목표가로 변경 |
| `/timing 005930 auto` | 자동 조건으로 변경 |
| `/timing_list` | 내 관심종목, 조건, 마지막 확인·시세 시각, 가격, 발송 결과 조회 |
| `/timing_del 005930` | 종목 알림 해제 (등록된 회사명으로도 가능) |

채팅당 최대 20개를 등록할 수 있습니다. 종목코드로 등록하면 이름이 비슷한 기업을
명확히 선택할 수 있습니다. 외부 API 장애 중에도 목록 조회·해제가 가능합니다.

## 자동 조건

다음 두 조건을 **모두** 충족해야 알립니다.

1. RSI(14, Wilder 평활)가 30 이하
2. 최신 가격이 20거래일 평균가 이하

지표는 최근 6개월의 확정된 수정 종가와 당일 최신 5분봉 종가를 사용합니다.
진행 중인 당일 일봉은 제외하고 최신 가격을 한 번만 반영합니다. 따라서 장중 RSI와
평균가는 잠정값이며 종가 확정 뒤 달라질 수 있습니다. 가격 비교에는 반올림 전 값을 씁니다.
일봉이 부족하거나 유효하지 않으면 자동 신호를 만들지 않습니다. 목표가 조건은
일봉 지표 없이도 최신 가격을 확인할 수 있으면 동작합니다.

RSI 30 이하는 통상 과매도 구간으로 해석합니다. 지속적인 하락에서도 조건이 충족될 수
있으므로 알림은 **등록 조건에 따른 매수 검토 신호**이며 반등·수익 보장이 아닙니다.
설명 참고: [Fidelity RSI 지표 안내](https://www.fidelity.com/learning-center/trading-investing/technical-analysis/technical-indicator-guide/RSI).

## 확인·발송 정책

- 한국 시간 평일 **09:05부터 15:05까지 매시 5분**에 확인합니다.
- 정규장 밖과 주말은 조회하지 않습니다. 공휴일·휴장일에는 당일 거래 시세가 없으면 발송하지 않습니다.
- Yahoo Finance의 국내 주식 시세(`.KS`, `.KQ`)를 yfinance로 조회합니다. 실시간 체결가가 아닌
  **지연될 수 있는 5분봉 종가**이며, 시세 기준시각은 5분봉의 시작시각입니다.
- 당일 정규장 내 시세, 양수 가격·거래량, 기준시각이 확인 시점으로부터 **20분 이내**인 경우에만 판정합니다.
  잘못된 시각·미래 시세·이전 거래일 가격·거래 없는 시세로는 알리지 않습니다.
- 같은 종목은 사용자별로 **하루 최대 1회** 발송합니다. 조건이 계속 충족되어도 반복하지 않고,
  다음 거래일에도 충족되면 다시 알릴 수 있습니다.
- 관심종목과 발송 기록은 SQLite에 저장되므로 재시작 후에도 유지됩니다. 당일 조건을 변경해도
  기존 발송 기록은 유지합니다. 삭제 후 새로 등록하면 새로운 구독으로 시작합니다.
- 실패한 전송은 성공으로 기록하지 않고 다음 시간에 조건을 재확인합니다. 봇을 차단한 채팅의
  해당 관심종목 알림은 해제합니다. 다른 사용자의 확인·발송은 계속 진행합니다.

알림은 기업명·종목코드, 가격, 충족 조건, 자동 지표, 시세 기준시각·출처를 포함합니다.
목록의 ‘마지막 확인’은 서버가 확인한 시간이고 ‘시세’는 가격 자료의 기준시각입니다.

## 실행·설정

기존 `simple_fast_api/.env`와 `TELEGRAM_BOT_TOKEN`을 사용합니다. 추가 키나 AI 호출은 필요하지 않습니다.
기존 서버 시작 조건인 `DART_API_KEY`는 설정되어 있어야 합니다. 서버를 재시작하면 DB 테이블과
명령어 메뉴, APScheduler 작업(`timing_alerts`)이 자동 등록됩니다.

```powershell
cd simple_fast_api
.venv/Scripts/python.exe main.py
```

서버와 Telegram polling 봇이 계속 실행 중이어야 확인·발송합니다. 서버 중지 동안의 신호는
소급 발송하지 않습니다. polling과 스케줄러는 **한 프로세스**로 실행하세요. 다중 worker에서의
분산 발송 잠금은 지원하지 않습니다. 프로세스가 Telegram 전송 직후 DB 기록 전에 중단되거나
전송 성공 응답을 받지 못하면 중복 수신 가능성이 있습니다.

정책 값은 `simple_fast_api/config.py`의 `TIMING_*`에 모여 있습니다. 시세 캐시는 회사명 원문 키와
종목코드 확인을 사용하며 60초만 유지합니다. 한 확인 주기에는 동일 종목 시세를 사용자 간에 공유하고,
외부 조회는 최대 4개씩 스레드로 실행합니다. 구현은 `services/timing.py`, 명령·발송은 `bot.py`,
영구 저장은 `database.py`, 예약 실행은 `main.py`가 담당합니다.

## 검증

```powershell
cd simple_fast_api
.venv/Scripts/python.exe -m unittest tests.test_timing -v
.venv/Scripts/python.exe -m unittest discover -s tests
```

테스트는 임시 DB와 가짜 시세·Telegram 전송을 사용합니다. 실제 관심종목이나 사용자에게
메시지를 보내지 않고 RSI 계산, 조건 경계, 캐시, 사용자 격리, 영속 기록, 중복 억제,
발송 재시도, 휴장·오래된 시세, 수집 중 등록 변경·해제를 검증합니다.

2026-10-24 검증: 신규 25건 통과, 임시 DB·가짜 봇으로 서버 HTTP 200과 예약 작업 등록을
확인했습니다. 동일한 환경의 전체 회귀는 변경 전 169건과 변경 후 194건 모두 기존 오류 11건·
실패 1건으로 오류·실패 목록이 같았습니다. 기존 오류는 Windows 캐시 파일 정리,
실패는 GitHub 소개의 AI 환경 관련 테스트입니다. 실제 Yahoo 시세 조회는 수집에 실패하여
라이브 연동을 확인하지 못했습니다. 실제 Telegram 전송도 수행하지 않았습니다.
