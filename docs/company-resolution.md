# 기업 식별과 검색 실패 안내

기업명 검색은 `services.dart.get_company_info()`를 공통으로 사용합니다.
대소문자, 공백·보이지 않는 공백, 유니코드 전각 문자, 앞뒤의 `주식회사`·`(주)`·`㈜`
표기를 통일합니다. 상호 내부의 기호는 보존하며 임의의 오타·별칭을 추측하지 않습니다.
6자리 종목코드도 입력할 수 있습니다.

DART 기업 목록에는 합병·상장폐지된 과거 법인도 남습니다. `stock_code`가 있다는
이유만으로 현재 상장사라고 판단하면 안 됩니다. 정규화한 상호가 중복되면
DART 기업개황의 `corp_cls`를 조회하고, 현재 상장 구분(Y/K/N)에 해당하는 기업이
한 곳일 때만 자동 선택합니다. 기업개황은 하루 단위로 제한적으로 재사용합니다.
복수 상장사 또는 상장사 없음은 404와 후보 종목코드로 안내하며,
확인 API 장애는 503으로 구분합니다. 종목코드를 직접 입력하면 해당 법인을 선택합니다.

신성이엔지 사례에서는 목록에 같은 이름으로 남은 과거 법인 `00686068 / 104110`을
먼저 선택하던 문제가 있었습니다. 2026-10-17 DART 기업개황 확인 결과 이 법인은
E(기타), 현재 신성이엔지 `00136271 / 011930`은 Y(유가증권시장)였습니다.
특정 기업의 이름이나 고유번호를 검색 예외로 하드코딩하지 않습니다.

기업 목록은 24시간마다 갱신합니다. 새 ZIP의 지정 XML만 파싱·검증한 후 원자적으로
교체합니다. 갱신 실패 시 기존 유효 목록을 유지하고 재시도를 잠시 늦춥니다.
파일이 바뀌지 않으면 파싱 결과와 정규화한 상호 목록을 메모리에서 재사용합니다.
기존 목록도 없으면 503을 반환합니다. 이전 식별 결과로 만들어진 조회 캐시는
캐시 스키마 버전 변경으로 무효화합니다.

`GET /companies/resolve/{기업명 또는 종목코드}`는 정식명·고유번호·종목코드를
반환하며 재무자료나 AI를 호출하지 않습니다. `cached`는 이 식별 응답 자체의 캐시
여부이며, 기업 목록·개황의 내부 재사용과 별개입니다.
Telegram `/chat`도 이 API로 시작하므로 재무자료가 없더라도 상담을 시작할 수 있습니다.
표시 이름과 조회용 종목코드를 분리해 후속 질문에서도 선택한 법인을 유지합니다.
다른 명령에서도 기업 식별 실패, 해당 자료 부재, 외부 API 오류를 구분해 안내합니다.

예: `/chat 신성이엔지`, `/chat 신성 이엔지`, `/chat 011930`.
같은 기업의 다른 입력 표기는 데이터 캐시 키를 합치지 않으며 원문 입력을 유지합니다.
