# 공시 전체 검색 기반 상담

`/chat LG전자`를 시작하고 다음처럼 질문합니다.

- `사업영역과 각 사업부의 주요 제품을 설명해줘`
- `경쟁력과 주요 위험 요인을 근거와 함께 설명해줘`
- `MS 사업부의 경쟁력은?` → `그 위험은?` → `더 설명해줘`
- `2024년 사업구조는?`
- `2023년과 2024년 사업구조 비교`

추가 유료 API·임베딩 모델 없이 CPU와 SQLite FTS5로 검색합니다. 공시 원문을
제목·문단·표로 나누고 한국어 2/3글자 토큰 및 영문 키워드로 색인합니다.
동의어와 사업부 약어를 함께 검색하며, 모델에는 선택한 근거 일부만 전달합니다.
4K 문맥·현재 로컬 모델 설정은 유지합니다. `/ask`는 공시 조회 없는 일반 질문입니다.

처음 질문하면 최신 정정 사업보고서를 가져와 색인하므로 시간이 더 걸립니다.
회사의 고유코드·공시 접수번호·색인 버전으로 저장하며 이후에는 다시 다운로드하지 않습니다.
공시 목록 캐시가 갱신돼 새 정정본을 발견하면 새 접수번호를 색인합니다.
숫자·사업부별 손익은 기존 조회·합계 대조·Python 계산 경로를 유지합니다.
내재가치·DuPont·분기 분석은 기존 도구를 사용하며 공시 검색 도구도 제공합니다.

답변에는 `[R1]` 등의 근거 번호와 보고서명, 재무 기준연도·결산월, 공시일,
수집시각, 원문 파일·조각 위치, DART 원문 링크를 붙입니다. 검색된 부분에 한정한
설명이며 보고서 전체를 종합 분석한 것처럼 표시하지 않습니다.
한 번에 최대 두 연도의 사업보고서를 비교 검색합니다. 없는 연도나 범위를 넘는
요청을 최신 연도로 바꾸어 답하지 않습니다. 같은 공시의 과거 수치가 회계 재작성된 경우와
조직 개편에 따른 사업부명 변경은 별도로 주의해야 합니다.

모델이 없는 근거 번호를 인용하거나 인용한 근거와 다른 숫자·부호·단위를 쓰면
생성 답변 대신 실제 원문 발췌를 보여줍니다. 원문에 없는 약어 풀이도 검사합니다.
첫 생성 답변이 검증에 실패하면 수치·약어 추측을 제외한 설명으로 한 번만 재시도하고,
동일한 검증을 통과하지 못하면 원문 발췌로 전환합니다.
이는 오류를 줄이는 장치이며 모든 문장의 의미까지 자동으로 검증하는 것은 아닙니다.
근거 자체가 없으면 없다고 안내하고 모델에게 추측을 요청하지 않습니다.
키워드 검색이므로 질문을 사업·제품·사업부 등으로 구체화하면 더 잘 찾을 수 있습니다.

`GET /evidence/{company_name}?query=...`는 모델 호출 없이 검색 근거를 반환합니다.
`cached`는 원문 색인 재사용 여부입니다. `answer_cached`는 동일 질문·대화·근거의
검증 답변 재사용 여부이며 자세한 조건은 [응답 속도 개선](response-performance.md)을 참고하세요.
`GET /cache/status`의 `report_search`에서 색인 수를 확인하고,
`DELETE /cache/clear?company_name=...`로 회사별 캐시·색인을 지울 수 있습니다.
색인은 `simple_fast_api/.cache/report_search.sqlite3`에 저장되며 커밋하지 않습니다.

원문 ZIP 안의 문서 합계는 최대 80MiB, 분할 후 텍스트는 최대 40Mi자입니다.
한도를 넘으면 앞부분만 읽은 결과를 전체 자료처럼 제공하지 않습니다.
이 PC의 가상 약 20MiB 문서 검증에서는 색인 약 9초, SQLite 약 34MiB가 소요됐고
문서 끝의 고유 문장까지 검색됐습니다. 실제 공시는 표·문자 구성에 따라 달라집니다.
