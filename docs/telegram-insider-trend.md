# Telegram 내부자 주식 매매 추이

`/insider 삼성전자`는 올해를 포함한 최근 3개년의 월별 주식 매수·매도 수량과
연간 합계를 PNG로 전송합니다. 올해는 조회일까지 집계합니다.
보통주·우선주 수량을 합산하며 금액이나 순보유량 그래프가 아닙니다.

`GET /insider-trend/{company_name}`는 같은 그래프의 입력 데이터를 반환합니다.
기존 `/insider/{company_name}`의 소유주식 증감 API는 유지합니다.

## 데이터 기준

- DART 공시 목록 `D002`, `last_reprt_at=Y`의 모든 페이지를 조회해 최종 보고서만 수집합니다.
- 원문 ZIP의 본문 XML에서 `RPT_RSN`(사유), `MDF_DM`(거래일), `STR_KND`(증권 종류),
  `MDF_STK_CNT`(증감 수량)를 읽습니다. 합계 행은 집계하지 않습니다.
- 장내·장외·시간외·공개 매수/매도가 명시된 주식 거래만 집계합니다.
  보유량 증감의 부호로 매매를 추정하지 않습니다.
- 증여·상속·옵션 행사·보상·신규보고·증자·비주식 증권 등은 제외합니다.
- 수량은 신고 거래일에 배치합니다. 조회일까지 접수된 공시만 포함하므로 미신고·지연 신고 거래는
  알 수 없고, 주식분할 전후 수량을 현재 주식 수로 소급 조정하지 않습니다.

## 실패와 캐시

원문 일부를 읽지 못하면 `coverage_complete=false`와 확인/미확인 건수를 제공합니다.
이때 수량은 확인된 공시분만의 하한이며 전체 매매 수량이 아닙니다.
집계되지 않은 0은 `null`로 표시합니다. 그래프와 Telegram 설명에도 이 한계를 표시합니다.

회사별 집계와 접수번호별 원문 파싱 결과를 각각 캐시합니다. 부분 집계는 5분 후 누락 원문을
재시도하고, 전체 성공 결과는 당일·TTL 범위 안에서 재사용합니다. 목록 갱신 실패 시 기존
스냅샷을 수집 기간과 갱신 실패 안내와 함께 표시합니다. 캐시가 없고 목록 조회가 실패하면 502입니다.

공시 수집은 초당 5건·동시 8건으로 제한하고 연속 오류 시 나머지 수집을 중단합니다.
실패한 원문은 정상 캐시로 저장하지 않습니다. 원문 캐시는 diskcache 내장 LRU와 50MB 용량 제한을
사용하여 수천 접수번호의 순서 목록을 매번 다시 기록하지 않습니다.
원문 캐시 키에는 파서 버전을 포함해 파싱 규칙 변경 전 결과가 재사용되지 않도록 합니다.

Telegram 명령과 추천 기업 버튼은 관리되는 비동기 작업으로 수집을 시작합니다.
최초 수집 중 다른 사용자의 도움말·명령 응답을 막지 않습니다. 최대 대기 시간은 15분입니다.

`simple_fast_api`에서 `.venv/Scripts/python.exe -m unittest discover -s tests -p test_insider_trend.py -v`.
거래 사유, 주식 종류, 날짜·수량 오류, 합계 행 중복, 페이지네이션, 캐시, 404/502,
부분 수집, PNG와 Telegram 캡션을 외부 AI 호출 없이 검증합니다.
