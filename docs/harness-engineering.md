# 하네스 엔지니어링 (Harness Engineering)

> 이 문서는 하네스 엔지니어링의 개념을 정리하고, 본 저장소에 어떻게
> 적용했는지 설명합니다. 참고 출처는 문서 하단에 있습니다.

## 1. 하네스 엔지니어링이란?

**하네스 엔지니어링(Harness Engineering)** 은 AI 에이전트(Claude, Codex 등)가
특정 프로젝트의 코드베이스·워크플로우·규칙을 일관되고 예측 가능하게 따르도록
**구조화된 가이드와 도구(하네스)** 를 설계하는 공학적 실천법입니다.

기존의 **컨텍스트 엔지니어링(Context Engineering)** 이 "한 번의 프롬프트에 무엇을
넣을지"를 다룬다면, 하네스 엔지니어링은 그보다 한 단계 위에서 **"에이전트가
반복적으로 일하는 환경 전체"** 를 설계합니다. 즉, 프롬프트 한 줄이 아니라
프로젝트 안내서·실행 도구·검증 장치·전문 에이전트 팀을 함께 갖추는 것입니다.

> 비유: 새 팀원에게 던지는 단발성 지시(컨텍스트)가 아니라, 온보딩 문서 +
> 개발 환경 + 코드 리뷰 프로세스 + 역할 분담(하네스)을 마련하는 것.

## 2. 하네스의 3대 구성 요소

| 요소 | 설명 | 본 저장소 위치 |
|------|------|----------------|
| **AGENTS.md** | 에이전트용 온보딩 문서. "이 프로젝트에서 어떻게 행동할지"를 정의 | `AGENTS.md` |
| **Skills** | 에이전트가 수행할 구체적 능력·절차 (점진적 공개) | `.claude/skills/`, 슬래시 커맨드 |
| **Rules** | 반드시 지켜야 할 제약·컨벤션·경계 | `AGENTS.md`의 도메인 규칙/경계 절 |

이 외에 넓은 의미의 하네스에는 **리포지토리 구조, CI/CD 파이프라인, 린터·포매터,
아키텍처 제약, 프로젝트 지시 파일(CLAUDE.md / AGENTS.md / .cursorrules)** 이
모두 포함됩니다.

## 3. AGENTS.md 작성 원칙

2,500개 이상 리포지토리 분석에서 도출된, 효과적인 AGENTS.md의 6개 핵심 영역:

1. **실행 가능한 명령어를 전면에** — 빌드·테스트·실행 명령을 문서 앞부분에 배치하고,
   도구 이름만이 아니라 플래그·옵션까지 명시합니다 (`npm run lint`, `uvicorn main:app --reload`).
2. **테스트/검증 방법** — 에이전트가 변경을 스스로 확인할 수 있는 절차.
3. **프로젝트 구조** — 디렉토리 역할과 계층 규칙.
4. **코드 스타일** — 추상적 설명 여러 문단보다 **실제 코드 스니펫 하나**가 효과적입니다.
5. **Git 워크플로우** — 브랜치·커밋·PR 규칙.
6. **경계(Boundaries)** — 절대 하지 말아야 할 일을 명확히 규정.

> AGENTS.md는 엄격한 스키마가 없는 평범한 마크다운입니다. 프로젝트 필요에 맞게
> 자유롭게 구성하되, 위 6개 영역을 빠뜨리지 않는 것이 핵심입니다.

## 4. 에이전트 팀 아키텍처 패턴

복잡한 작업은 단일 에이전트 대신 **전문 에이전트 팀**으로 분해·조율합니다.
대표적인 6가지 패턴:

| 패턴 | 특징 |
|------|------|
| 파이프라인 | 순차적 의존 작업 처리 |
| 팬아웃/팬인 | 병렬 독립 작업 후 통합 |
| 전문가 풀 | 상황별 선택 호출 |
| 생성-검증 | 생성 후 품질 검수 단계 |
| 감독자 | 중앙 에이전트의 동적 분배 |
| 계층적 위임 | 상위→하위 재귀적 위임 |

**Progressive Disclosure(점진적 공개)**: 스킬·컨텍스트를 한 번에 모두 노출하지
않고 필요한 단계에서 단계적으로 공개하여 컨텍스트 효율을 최적화합니다.

## 5. 본 저장소에 적용된 하네스

이 프로젝트는 **생성-검증(Generation-Verification)** 패턴을 채택했습니다.

```
메인 세션 (리더)
   │  구현 완료
   ├──▶ reviewer 서브에이전트  ─┐ 병렬 실행
   └──▶ tester 서브에이전트    ─┘ (서로 독립)
            │
            ▼
   구조화된 보고서 2종 → 메인 세션이 종합해 최종 판단
```

- **`.claude/agents/reviewer.md`** — 코드를 수정하지 않고 품질·보안·성능
  리뷰 보고서만 반환하는 검증 에이전트.
- **`.claude/agents/tester.md`** — 서버를 실제로 띄우고 API를 호출해 동작을
  검증하는 QA 에이전트.
- **`AGENTS.md`** — 두 에이전트와 메인 세션 모두가 공유하는 프로젝트 규칙·경계.

이 구성 덕분에 에이전트는 (1) AGENTS.md로 맥락을 파악하고, (2) 구현 후
reviewer·tester로 자가 검증하며, (3) Rules/Boundaries로 위험한 변경을 회피합니다.

## 6. 실천 체크리스트

새 기능을 추가하거나 에이전트 작업을 설계할 때:

- [ ] AGENTS.md의 명령어·구조·경계가 변경사항을 반영하는가?
- [ ] 새 상수·URL을 `config.py`에 모았는가? (하드코딩 금지)
- [ ] 블로킹 호출을 `asyncio.to_thread`로 감쌌는가?
- [ ] 404 폴백·캐시 플래그 등 도메인 규칙을 지켰는가?
- [ ] 구현 후 reviewer/tester로 검증했는가?
